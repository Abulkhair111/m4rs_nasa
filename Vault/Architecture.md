# Architecture

UE **5.8** (`A:/epic games/UE_5.8`), **Blueprint-only** (Visual Studio isn't installed, so no C++). Player-facing UI text is **English** (the editor UI may still be Russian).
Content root: `/Game/MissionCrew/{Core,UI,Maps,Data,Art}`.

## Networking
- **LAN listen server** (one player hosts). No dedicated server, no internet backend.
- Host: `OpenLevel L_Lobby?listen`. Join: `open <IP>` (UDP 7777) and/or LAN session search through OnlineSubsystemNull (the other agent added `WBP_LanSessionRow`; plugins OnlineSubsystem/Null/Utils are enabled).
- Planned: authority on the server. Every player action goes **through the PlayerController with a Server RPC** (actors the client doesn't own can't receive Server RPCs).

## Construction phase = Ice Return S1 "Design & Assembly" (`/Game/MissionCrew/Construction`)
Remade 2026-11-14 to the S1 spec in `../CONSTRUCTION_PHASE_ICE_RETURN.md` §3 (3D bay kept, roles and rules changed). Server-authoritative. Clients only display replicated state.
- **Roles (CrewRole number → S1 role):** 1 **Power Engineer** (Power & Comms shelf + cable reel), 2 **Construction Engineer** (Assembly Desk: rocket levers, wrench, LAUNCH), 3 **Propulsion Engineer** (engine, lidar, fuel tanks, fuel pump), 4 **Science Specialist** (instruments). The lobby still names the slots MCC Engineer / Flight Director / Pilot / Scientist; only the number matters here.
- **`BP_ConstructionManager`** (replicated, always relevant, one per bay): the single source of truth. Replicated: rocket (name, payload, cost, reliability, `SelectedLever`), `FuelKg`, `FuelMaxKg` (= total installed tank capacity; fuel is clamped to it), totals (`DryMassKg`, `TotalMassKg`, `TotalCostM`, `PowerGenW/UseW`, `StorageWh`, `DataMbps`, `BandwidthMbps`, `ScienceValue`, `Reliability`, `ThrustN`, `TWR`, `IceCount`, `UnboltedCount`, `OffGridCount`), `Checks[10]`, `DeptReady[5]`, accuracy `RoleGood[5]`/`RoleBad[5]`, `Report`, `Message`/`MessageTime`, `TimeLeft`.
  - `Recalc()`: for every socket with a part: mass, cost, tank capacity and reliability always count. A part is **live** if it is a tank (FuelCapKg > 0) or its socket has `bGrid`. Only live parts add power gen/use, storage, data, bandwidth, science, thrust, ice count, engine/lidar flags. Counts unbolted and off-grid parts. Then `RecalcChecks` → `BuildReport` + `UpdateAlerts`.
  - **Checks** (0 green, 1 yellow, 2 red): 0 launcher chosen · 1 mass (green ≤ 90% payload, red > payload) · 2 budget ($500M) · 3 power balance (red if gen < use or gen 0; green needs +10% and a battery) · 4 comms · 5 fuel (red if no tanks or fuel < 0.9 × dry; green needs +10% margin) · 6 thrust T/W = ThrustN / (total mass × 1.62) (red < 1.3 or no live engine; green ≥ 2.0 with lidar) · 7 ice science (red: no live ice-capable instrument; green: ≥ 2 and science ≥ 50) · 8 power grid (yellow if any module is off-grid) · 9 structure (red if any module unbolted).
  - Accuracy log: `Score(Role, Good)`. Install → good unless a Science part can't detect ice; wrench bolt → Construction good; cable toggle → Power good if gen ≥ use afterwards; every `RunPreflight` scores each role on its checks (Power 3, Construction 0/1/9, Propulsion 5/6, Science 7). `AccText()` appends "ACCURACY good/actions" per role to `Report`.
  - `ApplyTool(Target, ToolType)`: 1 = toggle the target's socket `bBolted`, 2 = toggle `bGrid` (tanks refuse). `TryLaunch` (all 4 READY, no red, yellow needs a second press) → `BP_MC_GameMode.ConstructionFinished`. `StartPhase()` spawns/possesses `BP_BayCharacter` at PlayerStarts tagged `Bay`. Auto-starts only on maps containing `L_AssemblyBay`. `bDebugAutoTest` runs a scripted build (rocket → install → wrench+cable via ApplyTool → fuel → READY ×4 → LAUNCH ×2) and prints `DEBUGTEST` lines.
- **Interaction:** `BP_BayCharacter` (first person, Enhanced Input `IMC_Bay` polled in Tick, `HoldPoint` 120 cm ahead). E edge → `ServerInteract` (server re-traces 350 cm with `FindTarget`) → carried item `CarrierAction`, else target `BP_BayInteractable.Use(Who)`. Release → `ServerRelease`. **Both events must be set to Run on Server by hand.**
- **`BP_BayInteractable`** base: `Prompt`, `Use/Release`, `GetPrompt(Who)`, helpers `Manager()`, `RoleOf(Who)`, `RoleAllowed(Who, Role)` (role 0 or `bFreeRoles` = allowed), `Valid(Obj)`.
  - `BP_Part`: `EventUse` → `HandleUse(Who)`: installed + bolted → refuse ("unbolt with the wrench first"); installed + loose → `RemoveFromSocket` (clears socket flags, refund) then grab; tools can only be grabbed by their department. `CarrierAction`: tool (`Def.ToolType > 0`) → `UseTool` (trace target; a BP_Part → `Manager.ApplyTool`, anything else → put the tool down); heavy part with one carrier → let go; else `TryPlace` → `Install` (attach, collision ON so the trace can hit it, socket bolted/grid reset, shelf respawn, Score, Recalc). `Drop` re-enables collision. `GetPrompt` shows "Bolts TIGHT/LOOSE · Power grid CONNECTED/OFF" for installed parts.
  - `BP_RocketLever` (role 2), `BP_FuelPump` (role 3, hold; `Rate` −100 = drain), `BP_ReadyButton` (`Department`), `BP_LaunchButton` (role 2).
- `BP_PartSocket` (`SocketType` 0 Power, 1 Battery, 2 Comms, 3 Science, 4 Drill, 5 Rover, 6 Engine, 7 Lidar, **8 Tank**; `Installed`, `bAlert`, **`bBolted`, `bGrid`** (replicated); ghost preview). `bAlert` (red pulsing marker) = installed but loose or off-grid, or a red check after preflight. `BP_PartShelf` (`Department`, `Parts[]`). Displays read the manager every tick: `BP_MassScale`, `BP_PowerStrip` (check 3), `BP_WallBoard` (+`WBP_WallBoard`, rows Check0–9, `UpdateRow9`), HUD `WBP_BayHUD`.

## C++ core (Agent E, 2026-11-14, written but NOT yet built)
The project is moving to C++ (VS 2022, MSVC 14.44). Nothing below was compiled: files were written while the editor was open. First build: close the editor, right-click the .uproject -> Generate Visual Studio project files (or run UBT with `-Project=` and the full path), then build `MissionCrewEditor Win64 Development`.
- **Module setup:** uproject `проект.uproject` (unchanged name) got a `Modules` entry `MissionCrew` (Runtime, Default). `Source/MissionCrew.Target.cs` (`MissionCrewTarget`) and `Source/MissionCrewEditor.Target.cs` (`MissionCrewEditorTarget`) use ASCII names on purpose: UBT only needs `<Name>.Target.cs` somewhere in `Source/`, the target name does not have to equal the uproject name. Module: `Source/MissionCrew/` (`MissionCrew.Build.cs`, `MissionCrew.h/.cpp` with `IMPLEMENT_PRIMARY_GAME_MODULE`, `LogMissionCrew`). Include root is the module dir, so write `#include "Construction/MCPartSocket.h"`. Native classes live under `/Script/MissionCrew`.
- **Construction files** (`Source/MissionCrew/Construction/`):
  - `MCConstructionTypes.h`: the shared contract. Enums `EMCSocketType`, `EMCCrewRole`, `EMCToolType`, `EMCCheckState`, `EMCCheck`; constants `MCConst`; `UMCPartDef` (UPrimaryDataAsset, same field names as `PDA_PartDef`); structs `FMCPreviewResult`, `FMCRocketDef`, `FMCLoadout(+Entry)`; delegate `FMCLaunchCompleteSignature`.
  - `MCPartSocket.h/.cpp`: `AMCPartSocket` (replicated state: `SocketType`, `Installed`, `InstalledActor`, `bBolted`, `bGrid`, `bReserved`, `bAlert`; server-only `Install/Remove/SetBolted/SetGrid/SetReserved`; `OnChanged` delegate; `BP_OnStateChanged` event for visuals).
  - `MCConstructionManager.h/.cpp`: `AMCConstructionManager` (replicated, always relevant). Same replicated fields as the BP plus `bLaunched` and `PhaseEndTime` (use `GetTimeLeft()`, avoids per-frame replication). `Recalc` + 10 checks + report + alerts, `Preview(Def)`, `GetCandidates`, `PlacePart` -> `OnPlacementApproved` (native delegate for the part mover) -> `FinishPlacement`, `RemovePart`, `ApplyTool`, `TryLaunch` (ready x4, no red, yellow needs a second press) -> `OnLaunchComplete(FMCLoadout)`, `Score`, `RunPreflight`, `Say`.
- **Flow for the game mode:** bind `Manager->OnLaunchComplete` and call `ConstructionFinished`. Clients cannot send Server RPCs on the manager (it has no owning connection): the pawn/controller RPC calls `PlacePart/ApplyTool/RemovePart/SelectRocket/AddFuel/ToggleReady/TryLaunch` on the server. If nothing is bound to `OnPlacementApproved`, `PlacePart` installs instantly (no animation).
- **Existing Blueprint assets are untouched.** `UMCPartDef` is a NEW class; `DA_Part_*` still use `PDA_PartDef`. Migration later: either add `UMCPartDef` assets generated by an editor Python script that copies the DA fields, or reparent `PDA_PartDef` to `UMCPartDef` (Class Settings; the BP's variables then clash with the C++ ones of the same name and must be deleted first, losing the DA values). Recommended: the script route. Same for `BP_PartSocket` -> replace in the level with `AMCPartSocket` (or a BP child of it), and `BP_ConstructionManager` -> a BP child of `AMCConstructionManager` for config (Catalog, Rockets).
- **Known risks:**
  1. Never compiled: expect small UHT/compile errors (first build will tell).
  2. **Cyrillic uproject name:** UBT defines `UE_PROJECT_NAME=проект` for modules under the project and `/Script/проект` is already in DefaultEngine.ini redirects. Editor (modular) builds should be fine, but monolithic packaged builds stringise that macro into `GInternalProjectName` through a compiler `/D`, which may mangle non-ASCII. If packaging breaks, rename the .uproject to ASCII (user decision, not done).
  3. `PDA_PartDef` field types are guessed (Department int, SocketType/ToolType as enums, Mesh hard `UStaticMesh*`); reconcile when migrating.
  4. Rule gaps filled by guess: Comms check (red no link / data > bandwidth, green +10%), Budget green <= 90%, Mass counts total (dry + fuel) vs payload, rocket table (Falcon 9 / Vulcan / Falcon Heavy numbers are placeholders), LanderBase mass/cost defaults (1200 kg / $100M; copy the BP values), phase duration 600 s with no hard consequence. `bDebugAutoTest` and `FuelRequired` UI wiring were not ported.
  5. Level sockets must be `AMCPartSocket` actors; old `BP_PartSocket` actors are invisible to the new manager.
  6. `Rockets = { {...} }` aggregate init of a USTRUCT; if the compiler complains, replace with explicit `Add`.
  7. Editing the .uproject while the editor is open: the editor will ask to rebuild/generate on next start; the first launch with a Modules entry and no built DLL prompts "Missing modules, rebuild?".

## Constructible rocket (Agent K, 2026-11-14, game target compiles)
- `Source/MissionCrew/Bay/MCRocketStack.h/.cpp`. `AMCRocketStack`: one per bay on the pad. Reads the installed ASCENT sockets (replicated `Installed`, so each machine builds the same visual locally; nothing extra to replicate) and rebuilds a modular stack from `UMCPartDef` data. Core bottom->top by `UMCRocketStackLibrary::CoreRank`: Engine, Tank, Decoupler, Other, Capsule, Fairing, then the lander mesh (`LanderMesh`) on top. Radial parts (`bRadial` or kind Booster): `RadialCount` copies each, all copies spread evenly around the core (1, 2, 4...). Each part's height/radius = `StackHeightCm`/`StackRadiusCm` or measured from the mesh bounds (rotation and scale applied, bottom-centre pivot); if `StackHeightCm` > 0 the mesh is uniformly fitted to it. No mesh = a gap of `EmptyPartHeightCm` (never an invented mesh).
- `UMCPartDef` new fields (category Stack): `StackKind` (EMCStackKind Other/Capsule/Fairing/Tank/Engine/Booster/Decoupler; Other = inferred from SocketType), `StackHeightCm`, `StackRadiusCm`, `bRadial`, `RadialCount`, `StackMesh` (soft; empty = fall back to `Mesh`+`MeshScale`), `StackMeshScale`, `StackMeshRotation` (local Z = rocket axis; fixes lying-down NASA models).
- New `EMCSocketType::Structure = 11` (ascent-only, self-powered, no cable) for decoupler/capsule/fairing parts. `MCIsAscentOnlyType` and `AMCPartSocket::IsSelfPowered` include it.
- Smoothing: new parts drop in (`DropHeightCm`), parts above glide up (`PartInterpSpeed`); whole stack scaled by `DisplayScale`, auto-reduced so height (ghost included) <= `MaxStackHeightCm` (3500). Manager totals unaffected.
- Ghost: `ShowGhost(const UMCPartDef*)` / `ClearGhost()` (local, ignores lander-group/tool defs). `UMCPartPickerWidget::UpdatePreview` calls them, `Close`/`NativeDestruct` clear. Material: `GhostMaterial` (default `/Engine/EngineDebugMaterials/M_SimpleTranslucent`; if it fails to load the ghost pulses).
- Socket helper: `UMCRocketStackLibrary::GetAscentSlots(FMCStackLayoutParams)` lists slots (core 0..N bottom-first: Engine, Tank, Structure; radial 0..3 Booster) with name `Ascent_<Kind>_<i>`, socket type, offset; `SpawnAscentSockets(World, Origin, Params, Class)` spawns `AMCPartSocket`s (SocketGroup Ascent, tags `AscentSlot` + name). `bAutoSpawnSockets` on the stack does this at BeginPlay (server, only if no ascent socket exists) and registers them with the manager.
- The stack only needs to know the ascent sockets exist; they can stay in the ASCENT zone. With `bHideSocketPartActors` their `AMCPartActor` visuals are hidden (the stack draws them).
- Perf: `StackMesh.LoadSynchronous()` on first use of a def (small hitch). Launcher lever (`Rockets`) is unchanged and does not alter the stack.

## S1 to S2 flow (Agent X, 2026-11-15) - `Source/MissionCrew/Core/MCMissionSubsystem.*`, Bay/Transit/Construction edits
**Why:** the flight deck is a separate map (`L_Transit`), so `AMCConstructionManager` (and the loadout) does not exist there.
