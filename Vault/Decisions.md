| 2026-11-14 | **Ice Return S1 "Design & Assembly" replaces the old construction rules** in the same 3D bay (user: "build design and assembly, remake current construction"). Brief §1 defaults used for the rest: numbers are placeholders (TBD), other submissions S2–S6 not started | User request. Keeps the working 3D bay and networking, so it still fits CONSTRUCTION_PHASE_ICE_RETURN.md S1 (4 roles on one shared lander, live totals, hard checks). |
| 2026-11-14 | S1 roles map onto the existing CrewRole numbers: 1 Power, 2 Construction (takes the old Director's lever/LAUNCH), 3 Propulsion, 4 Science | No lobby change needed (lobby is the other agent's). Per-submission role tables (brief §1 #2) come later with `BP_MC_GameState`. |
| 2026-11-14 | Construction Engineer "connects" modules with a **wrench** (bolt/unbolt); Power Engineer "connects modules to the grid" with a **cable reel** (on/off-grid). Tools are carried `BP_Part`s with `ToolType` | Physical, solo-testable, no new input actions. Bolted parts can't be pulled off, so departments must talk to the Construction Engineer. Off-grid parts give no power/thrust/science. |
| 2026-11-14 | Fuel needs installed tanks (`FuelMaxKg` = tank capacity). Thrust check = T/W on the Moon (1.62 m/s²) with the full wet mass | Brief S1 done criteria: "thrust covers the planned burns, fuel covers the flight with margin". |
| 2026-11-14 | Accuracy log kept per role (`RoleGood/RoleBad[5]`) in the manager, not per PlayerState | One player per role in S1, and it avoids touching the other agent's PlayerState. Move to GameState when submissions S2+ are built. |
| 2026-11-14 | **Part models come from NASA 3D Resources** (user: "take models and parts there science.nasa.gov/3d-resources"). Placeholders stay only where NASA has no fitting model (RTG, drill, rockets) | User-supplied source; free and without copyright. Animated GLBs are stripped of skins so they import as StaticMesh. |
| 2026-11-14 | Construction state lives in a replicated `BP_ConstructionManager` actor, not in `BP_MC_GameState` | Keeps the other agent's GameState untouched. GameMode only got `EnterConstructionPhase`/`ConstructionFinished`. |
| 2026-11-14 | Construction Server RPCs live on the pawn (`BP_BayCharacter`), parameterless; the server re-traces itself | The client owns its pawn, so RPCs work. Without params, the MCP-built events need only the "Run on Server" tick. Also anti-spoof. |
| 2026-11-14 | Part data = `PDA_PartDef` data assets, not a DataTable | MCP can't create UserDefinedStructs. Data assets are editable in the editor, and each holds its own mesh. |
| 2026-11-14 | Bay is its own map `L_AssemblyBay` (sublevel or travel target), built away from `L_Mission` | `L_Mission` belongs to the other agent. A separate map avoids conflicts and can be tested solo. |
| 2026-11-14 | Moon ground = flat engine plane + CC0 regolith material | Low-poly sphere looked faceted and made the rover float. |
| 2026-11-14 | **Moon terrain from real NASA LOLA DEM** (user approved), static mesh for the menu | Real craters and on theme. Low sun because the south pole sun is always near the horizon. Replaces the flat plane. |
| 2026-11-14 | Rover Nanite disabled | Project lacks SM6. Alternative: enable SM6 in Project Settings → Platforms → Windows. |
| 2026-11-14 | Git + LFS, source art in `SourceArt/` | Binary assets; avoid accidental auto-import. |
| 2026-11-14 | **Two separate stacks: LANDER and ASCENT/RETURN** (user request 2026-11-14). `EMCStackGroup {Lander, Ascent}`; `UMCPartDef.Group`, `AMCPartSocket.SocketGroup`; a part installs only on a socket of the same group. LANDER (lands on the Moon): science, gear/legs, rover, drill, lidar, solar, batteries, comms, RTG. ASCENT (take-off, orbit, return): solid boosters, fuel tanks, engines. **Fuel tanks can no longer go on the lander.** | Diverges from `CONSTRUCTION_PHASE_ICE_RETURN.md` §3 (S1 spec, not edited): there the lander is one stack with tanks. Rules: tank/engine/booster parts and sockets are forced to Ascent in code (`MCIsAscentOnlyType`), so a forgotten Group value cannot put fuel on the lander. New socket types `Booster` (9, self-powered, needs no cable) and `Gear` (10). The 10-check structure is unchanged; what changed: Fuel/Thrust use the ascent group (capacity from tanks, thrust = engines + live boosters, T/W = ascent thrust / (total mass lander+ascent+fuel x 1.62)); Thrust check passes with boosters alone; Ice/Comms/Science use the lander group; Power counts all consumers; Grid/Structure count both groups. Fuel required stays 0.9 x total dry mass (lander included). `GetCandidates` got a required Group argument. |

- **2026-11-14 (M2):** parts get their upright orientation from `PDA_PartDef.MeshRotation` and are bottom-aligned from component bounds (not from hand offsets), so replacing a mesh needs only a rotation if it is not Z-up. The single tools stand is the former assembly-desk shelf (tools respawn via HomeShelf). See [[Status]] Agent M2.
