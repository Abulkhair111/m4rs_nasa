# Mission Crew — роадмап разработки на Unreal Engine 5

NASA Space Apps Challenge 2026 · Space Mission Design Game
Кооп на 4 игрока: ЦУП (Инженер, Руководитель полёта) и экипаж (Пилот, Учёный).
Одна миссия на ~25 минут: найти лёд у южного полюса Луны.
**ЦУП знает, но не может. Экипаж может, но не знает.**

Источник: «Mission Crew: гейм-дизайн» (mind map) и «Mission Crew: как проходит миссия» (flow).
Состояние проекта на 14.11.2026: пустой Blueprint-проект на UE5, включён плагин MCP, git ещё не подключён.

## 1. Архитектура (Blueprints + DataTable, сеть с первого часа)

### Сеть
- **Listen-сервер без выделенного сервера, как «Открыть для сети» в Minecraft** (сделано). Один из игроков — хост, остальные видят его игру в списке автоматически.
  - Хост: `BP_MC_GameInstance.HostLAN` → `DestroySession` → `CreateSession` (LAN, 4 места) → `Open Level L_Lobby?listen`.
  - Клиенты: меню каждые 3 с вызывает `FindLANGames` (UDP-широковещание, порт **14001**) → список `WBP_LanSessionRow` → клик → `JoinLANGame` → `JoinSession`.
  - Запасной вход по IP (`open <IP>`) остался в меню.
  - OnlineSubsystem **Null** (`DefaultEngine.ini`), без Steam/EOS и без интернета.
- Игра через интернет: Radmin VPN или ZeroTier, порт **UDP 7777**. Это нужно проверить в первый же час. Автопоиск через VPN может не работать (широковещание), тогда входить по IP.
- **Сервер авторитетен.** Таймеры, физика посадки, поломки, ресурсы и очки считаются только на сервере, клиенты только отображают.
- ⚠️ Подвох UE: Server RPC работает только на акторе, которым владеет клиент. Поэтому все действия игроков (кнопка, клапан, тяга) идут через **`BP_MC_PlayerController` → Server RPC**, а не напрямую в актор комнаты.

### Классы
| Класс | Что хранит или делает |
|---|---|
| `BP_MC_GameMode` | Только на сервере: смена фаз, запуск поломок, подсчёт очков. |
| `BP_MC_GameState` (replicated) | `Phase` (RepNotify), `PhaseTimeLeft`, `MissionConfig`, ресурсы (масса, бюджет, энергия, данные, топливо), `ActiveFaults[]`, `EventLog[]`, `LanderState`, `Seed`. |
| `BP_MC_PlayerState` | `Role` (enum `E_Role`: Engineer / FlightDirector / Pilot / Scientist), `Callsign`. |
| `BP_MC_PlayerController` | Все Server RPC: `ServerSetComponent`, `ServerPilotInput`, `ServerRepairAction`, `ServerGoNoGo`… Создаёт UI своей роли. |
| `BP_MC_GameInstance` | Ник игрока, IP, переход между уровнями. |
| `BPFL_MC_Math` | Чистые функции: масса, бюджет, энергобаланс, объём данных за окно связи, очки, ранг. |
| `BP_FaultManager` (компонент на GameMode) | Seeded `Random Stream`, частота поломок зависит от надёжности компонентов, отсчёт 60–90 с. |
| `BP_LanderSim` (компонент) | Своя физика посадки (не Chaos). |

### Фазы: `E_Phase` на GameState
`Lobby → Briefing → Design → Launch → Transit → Landing → Surface → Ending → Debrief` (→ Design при перепроектировании).
Каждый клиент в `OnRep_Phase` переключает виджеты своей роли.

### Асимметрия информации
Все данные реплицируются всем игрокам, но **каждой роли показывается своё**:
| Роль | Видит | Делает |
|---|---|---|
| Инженер ЦУП | Всю телеметрию, коды ошибок (PWR, FUEL…) | Диагностику, распределение энергии, связь |
| Руководитель полёта | План, карту полюса, справочник ремонта | Go/no-go, точки проб, диктует процедуры |
| Пилот | Только приборы кабины | Старт, курс, посадку, ровер |
| Учёный | Панели и щиток кабины | Ремонт руками, бур, анализы |

На хакатоне защита от читерства не нужна, поэтому прятать данные на уровне сети незачем.

## 2. Данные (DataTable)

| Таблица | Поля (кратко) | Содержимое MVP |
|---|---|---|
| `DT_Components` | Id, Name, RealAnalog, Department (enum), MassKg, CostM, PowerW, Reliability 0–1, Tags, Description | Около 4 штук на отдел, в каждом дешёвый и дорогой вариант. Учёный — приборы как у VIPER (NIRVSS, NSS, MSolo, бур TRIDENT). Пилот — двигатель, бак, **лидар**, опоры. Инженер — панели, батарея, антенна. Руководитель — ракета. |
| `DT_Rockets` | Id, Name, PayloadToTLI_kg, CostM, Reliability | 3–4 ракеты. |
| `DT_Faults` | Code, Name, MccSymptom, CrewSymptom, ProcedureSteps[], TimeLimitSec, Consequence, TriggerComponentTag | PWR, FUEL, COMM, DRILL_HEAT |
| `DT_Events` | Id, Name, Phase, ChancePerMin, Effect | Солнечная вспышка, микрометеорит |
| `DT_LandingSites` | Id, Name, MapUV, IceChance, Slope, Illumination, CommVisibility | 4–6 точек с карты LRO (кратер Шеклтон и др.) |
| `DT_Tutorial` | Step, Role, Text, Trigger | Подсказки для первого запуска |

**Жёсткие проверки перед стартом:** масса ≤ грузоподъёмность ракеты, бюджет ≤ 500 млн $, топлива хватает на Δv перелёта и посадки.
**Мягкие ошибки проявляются в полёте:** нет лидара — посадка вслепую; маленькая антенна — меньше данных за окно связи; дешёвые компоненты — чаще поломки.

## 3. Механики по фазам (что должно работать в MVP)

| Фаза | Время | Механика | Кто |
|---|---|---|---|
| Лобби | 1 мин | Хост создаёт игру, остальные заходят по IP, каждый выбирает роль (роли не повторяются), кнопка «Готов». | все |
| Брифинг | 1 мин | Экран цели, бюджет 500 млн $, перекличка по позывным (каждый жмёт «на связи»). | все |
| Проектирование | 8–10 мин | Каждый правит **только свой отдел** в общей таблице ресурсов, которая обновляется вживую. Руководитель выбирает ракету. Кнопка «Старт» доступна, только когда пройдены жёсткие проверки. | все |
| Старт | 2 мин | Опрос go/no-go: Руководитель опрашивает, каждый подтверждает. Тангаж уплывает (шум из Random Stream), Пилот держит его в коридоре. Отделение ступени — по команде Руководителя, Пилот нажимает в окне ±N секунд. | Пилот, Руководитель |
| Перелёт | 2 мин | Инженер видит коррекцию (Δv, угол) и диктует её, Пилот вводит. Руководитель выбирает зону посадки по карте LRO. Учёный калибрует приборы (мини-задача на щитке). | все |
| Посадка | 3 мин | Своя физика (см. ниже). Без лидара у Пилота нет высотомера, высоту диктует ЦУП с задержкой. Не забыть выпустить опоры. | Пилот, Инженер |
| Поверхность | 7 мин | Ровер ездит по 2D-карте зоны. Бур сначала нагревается, потом даёт пробу, потом анализ. Энергия делится между **6 потребителями**. Данные копятся в буфере и уходят на Землю **только в окна связи**. Поломки. | все |
| Завершение | 1 мин | Последнее окно связи: выбрать порядок отправки (сначала самые ценные данные). | Инженер, Учёный |
| Дебриф | 2–3 мин | Очки, ранг S–F, лента событий с причинами, кнопка «Перепроектировать», которая возвращает в фазу Проектирования с той же конфигурацией. | все |

### Физика посадки (`BP_LanderSim`, тик на сервере)
```
g = 1.62 м/с²
a = Thrust/Mass − g        (Mass уменьшается с расходом топлива)
Vv += a·dt ; Alt += Vv·dt ; Fuel −= Throttle·BurnRate·dt
Касание: |Vv| < 2 м/с  И опоры выпущены  И |Vh| < 1  → мягкая посадка
          иначе → жёсткая (повреждения) или крушение
```
Пилот передаёт газ через Server RPC с частотой около 10 Гц, этого достаточно.

### Поломки: код у ЦУП → процедура у Руководителя → руки экипажа, 60–90 с
| Поломка | ЦУП видит | Экипаж видит | Ремонт |
|---|---|---|---|
| Перегрузка шины питания | Падает напряжение, код PWR | Мигает свет | Выключить 2 системы, сбросить автомат |
| Утечка топлива | Растёт расход, код FUEL | Шипение в отсеке | Закрыть клапан; номер клапана знает только ЦУП |
| Потеря связи | Телеметрия пропала | Индикатор антенны красный | Экипаж сам наводит антенну |
| Перегрев бура | Температура в красной зоне | Дым из бура | Стоп, охлаждение, ждать зелёного |

Вероятность поломки = базовая × (1 − Reliability компонента). Внешние события: солнечная вспышка (бьёт по электронике и связи), микрометеорит (утечка). Если не успели за таймер — последствия из `DT_Faults`.

### Очки (максимум 100)
```
Наука   60 × доля переданных данных   (непереданные данные не считаются)
Ремонты 20 × доля успешных ремонтов
Бюджет  10 × остаток бюджета / 500
Посадка 10 (мягкая) / 5 (жёсткая)
Крушение → итог 0 (−100)
Ранг: S 90+ · A 75+ · B 60+ · C 40+ · F <40
```
В ленте событий каждое событие хранит причину, например: «Мин. 14: потеря связи → антенна дешёвая (Reliability 0.6) + солнечная вспышка → 30% данных не передано».

## 6. Риски

| Риск | Что делаем |
|---|---|
| Сеть не работает | Чекпоинт в 14:00 субботы и план Б (сплит-скрин). |
| Server RPC «молча» не доходят | Все действия только через PlayerController (см. §1). |
| Не успеваем 3D-комнаты | Те же виджеты на весь экран без 3D. |
| Слишком много мини-игр | Обязательно: посадка, поверхность, 4 поломки, дебриф. Старт и перелёт можно упростить до одной кнопки и одного ввода. |
| Конфликты в `.uasset` | Владение ассетами (§5), предупреждать в чате перед правкой чужих файлов. |
| Нет интернета или порты закрыты на площадке | Radmin VPN или ZeroTier, проверить заранее; запасной вариант — свой роутер или LAN. |

## 7. Готово к сдаче, если
1. 4 игрока по сети (или в сплит-скрине) проходят миссию от лобби до дебрифа.
2. Каждая роль видит только свою часть информации, и без голосового общения миссию не пройти.
3. Работают жёсткие проверки на проектировании, а мягкие ошибки проявляются в полёте.
4. Есть 4 поломки и 2 внешних события, их частота зависит от выбора компонентов.
5. Дебриф показывает очки, ранг и причины событий, кнопка «Перепроектировать» работает.
